# ATHAHAR ROADWAYS — UPDATED IMPLEMENTATION PLAN

## 1. Objective

Build a modern React + Firebase transport management application for ATHAHAR ROADWAYS using the client's existing LIMRA **Inward and Outward** workflow as the business reference.

The application must preserve the client's transaction fields and working process while improving:

- UI/UX
- Search
- Filtering
- Data management
- Security
- Reports
- Printing
- Responsive behavior

---

# 2. Client Workflow

The two provided screens are:

- **First image: Inward**
- **Second image: Outward**

The complete workflow is:

```text
Existing Transport Document
          |
          | Existing LR No.
          v
       INWARD
          |
          v
   PENDING STOCK
          |
          | Select existing LR
          v
       OUTWARD
          |
          v
      DELIVERED
```

## Critical Rule — LR

**LR No. must never be generated by the application.**

It is already present on the client's external/physical transport document.

The operator manually enters the LR during Inward.

Outward uses the same LR.

# 8. Phase 6 — Inward Validation

Before saving:

### Required

- Date
- LR No.
- PKG
- Consignor
- Consignee where required

### Rules

1. LR cannot be blank.
2. LR is manually entered.
3. LR must not be generated.
4. Duplicate active/pending LR must be rejected.
5. PKG cannot be negative.
6. Amounts cannot be negative.
7. Valid master records must be selected.
8. Inward must contain at least one LR row.

The application is complete when:

- Inward matches the client's required business fields.

- Multiple LR Outward selection works.
- LR is manually entered.
- LR is never generated.
- Inward LR becomes Pending.
- Pending LR can be searched.
- Only Pending LR can be moved to Outward.
- Outward changes status to Delivered.
- Delivered LR cannot be processed again.
- Delivery Person is recorded.
- Totals are calculated correctly.
- Reports are accurate.
- Excel works.
- PDF works.
- Print works.
- Print Preview works.
- Audit logs work.
- Firebase security rules work.
- Responsive UI works.

# 29. Final Business Rule

```text
EXTERNAL / CLIENT DOCUMENT
          |
          | Existing LR
          v
       INWARD
          |
          v
       PENDING
          |
          | Same LR
          v
       OUTWARD
          |
          v
      DELIVERED
```

## LR is never generated by the system.

The application manages and tracks the LR; it does not create the LR.
